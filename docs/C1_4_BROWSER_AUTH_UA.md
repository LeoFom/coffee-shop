# Coffeo C1.4 — браузерне відновлення сесії

Гілка `codex/c1-4-browser-auth` працює з API `codex/c1-3-session-protocol`. Вона не змінює production Vercel/Render і не додає сервісів або секретів.

`getUser()` повертає `authenticated`, `needsRefresh`, `anonymous` або `unavailable`. Кожна приватна сторінка викликає `requireUser()` до завантаження приватних даних. При `needsRefresh` сервер переводить на `/auth/continue?next=...`; адреса повернення обмежена конкретними приватними шляхами. Сторінка відновлення викликає `POST /api/v1/auth/refresh`, потім `/api/auth/me`, і лише після підтвердження користувача повертає його на початкову сторінку. Cookie записує Route Handler, не Server Component.

Клієнтський `fetchWithAuth` спільно виконує один refresh для одночасних запитів і робить один повтор тільки при `401 ACCESS_EXPIRED` від guard. При 503 або втраті мережі мутація автоматично не повторюється. Checkout зберігає форму та попереджає про невідомий стан замовлення. При остаточному 401 Context очищує користувача, кошик і кеш продуктів. Після входу іншого користувача попередні дані очищуються негайно; запізніла відповідь старого запиту кошика не застосовується. Після успішного входу та відновлення кошик перечитується для поточного user ID.

Тести перевіряють allowlist адрес, один refresh для паралельних запитів, відсутність повтору мутації при 503 та відокремлення 401. Локальний браузерний тест із синтетичним API підтвердив перехід від простроченого access через recovery до Dashboard. Окремий branch-only CI запускає зафіксований SHA Fastify C1.3, Next BFF та одноразову PostgreSQL і перевіряє login → expired access → refresh → приватну сторінку → logout. Production дані та cookies для тесту не використовуються.
